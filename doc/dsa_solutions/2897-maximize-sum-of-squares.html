2897. Apply Operations on Array to Maximize Sum of Squares

HardGreedyBit Manipulation
leetcode.com/problems/apply-operations-on-array-to-maximize-sum-of-squares · Solved in C++ · 13 Oct 2026

Problem (short)

Given nums and k. Operation (any number of times): pick i ≠ j, then nums[i] = nums[i] AND nums[j] and nums[j] = nums[i] OR nums[j] (both use the old values).

Finally pick k elements and return the max sum of their squares, mod 1e9+7.

Intuition

  1. For a pair, AND + OR just moves 1-bits from one number to the other. No 1-bit is created or destroyed. So the count of 1s at each bit position never changes.
  2. Squares reward big, uneven numbers (x² + y² is larger when the numbers are far apart).
  3. So: pile all the bits into as few numbers as possible. The first number takes one bit from every position that still has a bit, the second does the same with what's left, and so on, for k numbers.
Ignore the operation. Just count bits per position, then build k numbers greedily.

Approach

  1. For every number, add its set bits into bit_count[0..31].
  2. Repeat k times: build curr by taking one bit from every position with count > 0, and decrement those counts.
  3. Add curr² (mod) to the answer.

Math

Let ci = number of elements with bit i set. The j-th number (1-indexed) gets bit i exactly when ci ≥ j:

vj = Σi 2i · [ ci ≥ j ]
answer = ( Σj=1..k vj² ) mod (10⁹+7)

Why spreading hurts (for AND = x, OR = y):

x + y = a + b (sum is fixed)
x² + y² = ( (x+y)² + (y−x)² ) / 2
→ bigger gap (y − x) ⇒ bigger sum of squares

OR is always ≥ both inputs, so every operation widens the gap or keeps it. Packing bits to the front is the limit of that.

General identity used: a + b = (a AND b) + (a OR b).

Code

#define MOD 1000000007

class Solution {
public:
    int maxSum(vector<int>& nums, int k) {
        int bit_count[32]{};
        unsigned long long square_sum = 0;

        // count all the total number of bits available in nums
        for (int num : nums) {
            for (int i = 0; i < 32 && num > 0; i++) {
                if ((num & 1) == 1) {
                    bit_count[i]++;
                }

                num >>= 1;
            }
        }

        // create number bit by bit using available bits
        for (int i = 0; i < k; i++) {
            int curr = 0;
            for (int i = 0; i < 32; i++) {
                if (bit_count[i] > 0) {
                    curr |= (1 << i);
                    bit_count[i]--;
                }
            }
            square_sum += ((long long)curr * curr) % MOD;
        }

        return (int)(square_sum % MOD);
    }
};

Complexity

TimeO(32·n + 32·k) = O(n)
SpaceO(32) = O(1)

Pitfalls & notes

  • Cast before multiplying: (long long)curr * curr. curr can be ~10⁹, so int × int overflows.
  • Accumulator is safe: each term is < MOD, with k ≤ 10⁵ terms the sum is ≤ ~10¹⁴, which fits in 64 bits. Final % MOD once at the end.
  • Inner loop re-declares i (shadows the outer one). It compiles and works, but rename it (b) to avoid confusion.
  • Values are < 2³⁰, so bit 31 is never set. 1 << i is safe.
  • If k is larger than the max count of any bit, later numbers just become 0. No special case needed.
  • Optional speed-up: break if curr == 0, since all later numbers are 0 too.
  • No sorting needed. Greedy numbers are already produced largest first.

Checked: both LeetCode examples (261, 90), 3000 random small cases against a brute force over all reachable arrays (0 mismatches), and the n = 10⁵ max case.

Pattern to remember

  • Operation preserves something (here: per-bit counts) → forget the operation, work with the invariant.
  • Maximize Σ x² with a fixed total → make values as uneven as possible.
  • Bit-position counting + greedy "build the biggest number first" also shows up in related AND/OR/XOR problems.
